# 導入手順（社内PC・共有フォルダ・スマホ）

> 管理者権限が必要な操作（ファイアウォール、タスク登録、証明書、共有フォルダの権限）は、**情報システム担当者の確認を得てから**実施してください。この手順書は「必要な設定と対象範囲」を示すもので、アプリが自動で変更することはありません。

## 0. 前提（暫定）と確認事項

社内環境が不明なため、次の構成を暫定前提にしています。

| 項目 | 暫定前提 | 確認すること |
|---|---|---|
| アプリサーバー | 社内の Windows 10/11 PC（常時起動） | 常時起動できるPCがあるか。スリープしない設定にできるか |
| 保存先 | 共有フォルダ（UNC パス、例 `\\fileserver\share\meishi`） | サーバーPCの実行用アカウントから読み書きできるか |
| 取り込み用フォルダ | 共有フォルダ（例 `\\fileserver\share\meishi-inbox`）。利用者が名刺画像を置く | 利用者・複合機から書き込めるか。複合機の「フォルダへスキャン」の保存先にできるか |
| 利用者 | 複数人。全員が全名刺を見られる（共有） | 利用者ごとのログインIDを発行する |
| スマホ | 社内 Wi-Fi からサーバーPCへ到達できる | Wi-Fi と サーバーPCのネットワークが通信可能か（ゲスト Wi-Fi は不可の場合が多い） |
| 社外利用 | 会社で認められた既存 VPN 経由のみ | VPN からサーバーPCへ到達できるか。独自トンネルや外部中継は使わない |
| NAS でのアプリ実行 | 使わない | NAS が Node.js やコンテナを実行できる場合でも、まずは Windows PC 構成を推奨（NAS 上で動かす場合も「アプリは1台だけ」の原則は同じ） |

**サーバーPCが停止・スリープしている間は、スマホからもPCからも利用できません。**

## 1. 必要なもの（すべて無料）

- **Node.js 22 LTS**（Windows 用 MSI。インターネットに接続できるPCでダウンロードし、社内PCに持ち込んでインストール可）
  - インストールできない場合は、Node.js 公式の Windows 用 zip に含まれる `node.exe` をアプリの `runtime\node.exe` に置けば動きます。
- 配布フォルダ `meishi`（下記 2. で作成）

## 2. 配布フォルダを作る（インターネット接続のある開発PCで1回だけ）

```bash
npm ci
```

```bash
npm run package
```

`release/meishi` ができます（約50MB。大半は OCR の日本語・英語データとエンジン）。これを社内PCの `C:\meishi` などにコピーします。以降、社内PC側でインターネット接続は不要です。

## 3. 実行用アカウントと共有フォルダの権限

アプリサーバーは**専用の実行用アカウント**で動かします（例：ドメインユーザー `CORP\svc-meishi`）。

| 対象 | 付与する権限 | 備考 |
|---|---|---|
| 共有フォルダ `\\fileserver\share\meishi`（データ） | 実行用アカウント：**変更**（NTFS の「変更」＝読み取り・書き込み・削除） | アプリはフォルダ内でファイルの作成・置き換え（rename）・削除・サブフォルダの入れ替えを行います |
| バックアップ先 `\\fileserver\share\meishi-backup` | 実行用アカウント：**変更** | 既定ではデータフォルダ内の `backups`。別フォルダ推奨 |
| 上記フォルダのその他の利用者 | **アクセス権なし**（管理者を除く） | 名刺は個人情報です。Everyone / Domain Users の権限は外してください。利用者はブラウザ経由で使うため、データフォルダへの直接アクセスは不要です |
| 取り込み用フォルダ `\\fileserver\share\meishi-inbox` | 実行用アカウント：**変更**。利用者のグループ（例 `CORP\名刺管理利用者`）と複合機のスキャン用アカウント：**書き込み**（フォルダ内の一覧表示・読み取りは必要に応じて） | 取り込み後の画像はアプリが**データフォルダ内の `inbox-done`**（利用者からは見えない）へ移し、`inboxRetentionDays`（既定90日）後に削除します。取り込み前の画像は利用者グループから見える点に注意してください |
| `C:\meishi\config`（パスワードのハッシュ・セッション） | 実行用アカウントと管理者のみ | 共有フォルダ・Git・バックアップには含めません |
| `C:\meishi`（アプリ本体） | 実行用アカウント：読み取り・実行（`logs` と `config` は書き込み） | |

- **マップドライブ（Z: など）は使わないでください。** タスクやサービスからは見えないことがあります。必ず UNC パスで指定します。
- ワークグループの NAS で NAS 側のユーザー名・パスワードが必要な場合は、実行用アカウントでログオンした状態で `cmdkey /add:fileserver /user:NASユーザー名 /pass` を実行し、Windows の資格情報マネージャーに保存します（アプリの設定ファイルや Git には書きません）。
- 実行用アカウントを `LocalSystem` にする場合は、共有フォルダ側にコンピューターアカウント（`CORP\サーバーPC名$`）の権限が必要になります。専用ユーザーの方が権限の範囲を管理しやすいため推奨します。

## 4. 設定

`C:\meishi\config\config.sample.json` を `config.json` にコピーして編集します。

```json
{
  "dataDir": "\\\\fileserver\\share\\meishi",
  "backupDir": "\\\\fileserver\\share\\meishi-backup",
  "host": "0.0.0.0",
  "port": 8443,
  "https": { "pfxPath": "C:\\meishi\\certs\\server.pfx", "pfxPassphraseEnv": "MEISHI_PFX_PASSPHRASE" },
  "autoBackup": { "intervalHours": 24, "keep": 14 },
  "sessionDays": 30
}
```

- JSON では `\` を `\\` と書きます（`\\fileserver\share` → `"\\\\fileserver\\share"`）。
- `https` を省略すると HTTP で起動します（5. 参照）。
- `inboxDir` を省略すると取り込み用フォルダの機能はオフになります（スマホ撮影・PCからのアップロードは使えます）。
- `keep` は自動バックアップの保持世代数です。1世代は「名刺JSON＋全画像」のサイズ（画像1枚 約100〜400KB）です。

## 5. HTTPS（推奨）

- 社内CAなど、**会社の運用で発行した証明書**（サーバーPCのホスト名、例 `meishi.corp.local` 用）を PFX 形式で `C:\meishi\certs\server.pfx` に置きます。パスフレーズは設定ファイルに書かず、実行用アカウントの環境変数 `MEISHI_PFX_PASSPHRASE` に設定します。
- iPhone がその社内CAを信頼している必要があります（通常は MDM や構成プロファイルで配布済み）。**自己署名証明書の手動インストールや、ブラウザの警告を無視する運用はしないでください。**
- HTTPS が用意できない場合でも、社内LAN内の HTTP で基本機能（撮影はファイル入力方式のため HTTP でも可）は動作します。ただし Wi-Fi 上をパスワードや名刺データが暗号化されずに流れるため、社内規程で許される場合に限ってください。
- HTTPS が必要になる機能：ホーム画面からの「アプリとして」の起動の一部挙動、ブラウザのカメラAPI。このアプリはカメラAPIを使わず `<input type="file" capture>` で撮影するため、HTTP でも撮影・登録できます。Service Worker は使っていません（名刺データを端末に残さないため）。

## 6. 初期化とパスワード設定

実行用アカウントでコマンドプロンプトを開きます（例：`runas /user:CORP\svc-meishi cmd`）。

```bat
cd /d C:\meishi
node dist\server\cli.js init-store
node dist\server\cli.js user add yamada --admin --name 山田
node dist\server\cli.js user add suzuki --name 鈴木
node dist\server\cli.js check
```

- `init-store` は保存先に `.meishi-store`（目印）と `cards` `images` `trash` `tmp` を作ります。既存データは消しません。
- アプリはこの目印が無い保存先には**書き込みません**（共有が外れたときに別の場所へ黙って保存しないため）。
- `check` で「書き込み確認: OK」と出れば準備完了です（取り込み用フォルダの読み書き可否も表示）。

### 利用者の管理（サーバーPCで実行）

| 操作 | コマンド |
|---|---|
| 追加（一般利用者） | `node dist\server\cli.js user add <ID> --name 表示名` |
| 追加（管理者） | `node dist\server\cli.js user add <ID> --admin --name 表示名` |
| パスワード変更・リセット | `node dist\server\cli.js user passwd <ID>`（その利用者のログイン中の端末は無効になります） |
| 削除（退職・異動時） | `node dist\server\cli.js user remove <ID>`（ログイン中の端末も即時無効） |
| 一覧 | `node dist\server\cli.js user list` |

- 全員が全名刺を閲覧・登録・編集できます。名刺には登録者・最終更新者を記録し、詳細画面に表示します。
- **管理者のみ**：バックアップの作成・ダウンロード、復元、CSV出力（全件の持ち出し・置き換えにあたるため）。
- パスワードは本人が決め、サーバーPCで本人に入力してもらうか、仮パスワードを伝えて変更してもらいます（現在、画面からのパスワード変更機能はありません）。
- `seed-dev`（架空データ投入）は `init-store --dev` で作った開発用の保存先でしか動きません。本番では使いません。

## 7. 起動

### 手動起動（動作確認用）

```bat
C:\meishi\scripts\windows\start-server.cmd
```

ログは `C:\meishi\logs\server.log` に出ます（名刺内容・連絡先・パスワード・検索語は出力しません）。

### PC 起動時に自動起動（管理者が実施）

管理者権限の PowerShell で（内容を確認してから）：

```powershell
C:\meishi\scripts\windows\register-task.ps1 -User CORP\svc-meishi
```

- タスク「MeishiServer」が登録され、PC起動時（ログオン不要）に実行用アカウントで起動し、異常終了時は1分後に再起動します。
- 起動直後に共有フォルダへ接続できない場合は、**接続できるまで15秒ごとに待機**します（その間、別の場所に保存することはありません）。
- サーバーPCのスリープを無効にしてください（例：`powercfg /change standby-timeout-ac 0`）。

## 8. ファイアウォール（管理者が実施・要確認）

受信を許可するのは**アプリのポートだけ、社内ネットワークからだけ**にします。例（社内 Wi-Fi が 192.168.10.0/24 の場合）：

```powershell
New-NetFirewallRule -DisplayName "Meishi (TCP 8443)" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow -Profile Domain,Private -RemoteAddress 192.168.10.0/24,LocalSubnet
```

- Public プロファイルでは許可しません。ルーターのポート開放などで**インターネットへ公開しないでください。**
- 社外からは、会社が認めた既存 VPN でサーバーPCへ到達できる場合だけ利用します。

## 9. 取り込み用フォルダ（複合機・PCから名刺画像を入れる）

1. 取り込み用フォルダに名刺画像を入れます。
   - **複合機**：「フォルダへスキャン（SMB）」の保存先を取り込み用フォルダにし、形式は **JPEG**、解像度は 300dpi 程度、カラーを推奨。名刺1枚＝1ファイルになるように読み取ります（表裏は別ファイルで可）。PDF は取り込めません。
   - **PC**：エクスプローラーで画像をコピー。
   - 対応形式：JPEG・PNG・WebP（HEIC は iPhone/Mac の Safari でのみプレビュー・取り込み可）。30MB まで。
2. アプリの「未整理」を開くと画像が一覧表示されます（置いてから10秒ほど後。複合機が書き込み中のファイルを避けるため）。
3. 1〜2枚を選んで「選んだ画像で登録」（1枚目＝表、2枚目＝裏）。OCR の候補も使えます。内容を確認して「保存」すると、元画像は取り込み済みへ移動します。
4. 誤ってスキャンしたものは選んで「破棄」（取り込み済みへ移動。名刺としては登録しません）。

- 画像は自動で名刺として登録されません。必ず誰かが画面で内容を確認して保存します。
- 複数人が同じ画像を開いた場合は「○○さんが作業中」と表示し、同じ画像での二重登録は拒否します。
- アプリが取り込み用フォルダに接続できないときは、「未整理」画面にエラーを表示します（名刺の保存には影響しません）。
- iPhone の「ファイル」アプリから共有フォルダへ直接保存する方法もありますが、スマホに共有フォルダの接続情報を設定する必要があり、社内規程で許可されない場合があります。**スマホからはアプリの「📷 撮影」を使う**ことを推奨します。

## 10. スマホから使う

1. スマホを社内 Wi-Fi（または承認済み VPN）に接続します。
2. Safari で `https://サーバー名:8443/`（HTTP 運用時は `http://サーバー名またはIP:8443/`）を開きます。
3. ログインIDとパスワードでログインします（ログイン状態は既定で30日間保持。ログアウトは「管理」画面）。
4. 共有ボタン →「ホーム画面に追加」でアプリのように起動できます（通常のブラウザ利用でも全機能を使えます）。
5. 登録：下部の「＋新規登録」→「📷 撮影」で名刺を撮影 →（任意）「文字を読み取る」で候補を確認して反映 → 内容を確認して「保存」。

サーバーPCが停止しているとき、または社外で VPN に接続していないときは利用できません（画面上部に「サーバーに接続できません」と表示されます）。

## 11. 運用

### 停止

```powershell
Stop-ScheduledTask -TaskName MeishiServer
```

手動起動の場合はウィンドウで Ctrl+C。保存処理の途中で止まっても、名刺ファイルは「置き換え前」か「置き換え後」のどちらかが残るように書き込んでいます。

### 更新

1. 管理者で「管理」→「今すぐバックアップを作成」
2. タスクを停止
3. 新しい `release/meishi` の `dist` `public` `scripts` `docs` を上書き（`config` `logs` `runtime` は残す）
4. タスクを開始し、画面で動作と件数を確認

### バックアップ

- 自動：起動1分後と以降1時間ごとに確認し、前回から `intervalHours` 経過していれば画像込みの全件バックアップ（`.tar`）を作成、`keep` 世代を超えた古い自動バックアップを削除します。
- 手動：「管理」→「今すぐバックアップを作成」。各バックアップは「ダウンロード」できます。
- **同じ共有ストレージ（同じ NAS）内のバックアップでは、NAS 自体の故障・ランサムウェア・誤削除には備えられません。** 定期的に（例：月1回）バックアップをダウンロードし、会社の規程に沿った**別の社内媒体**にも保管してください。
- バックアップは名刺データと画像のみで、パスワードや設定は含みません。個人情報を含むため、保管先の権限もデータと同様に制限してください。
- `.tar` は Windows 標準の `tar -xf ファイル名` でも中身（`cards/*.json`・`images/*.jpg`・`manifest.json`）を確認できます。

### 復元

「管理」→ 一覧の「この時点に復元」または「バックアップファイルを選んで検証」。形式・ハッシュ・名刺データ・画像参照を検証し、件数を確認したうえで「復元」と入力して実行します。実行前のデータは「復元前の退避」バックアップとして自動保存されます。

### トラブル時

| 症状 | 対処 |
|---|---|
| 画面上部に「保存先（共有フォルダ）に接続できません」 | ネットワーク・NAS・権限を確認。復旧後30秒以内に自動で再接続します。切断中の保存は失敗として表示され、入力内容は画面に残ります |
| 起動ログに「別のサーバーがこの保存先を使用中」 | 別のPCで同じ保存先のアプリが動いていないか確認して停止。異常終了の残りであれば2分で自動的に引き継ぎます（急ぐ場合は他が動いていないことを確認のうえ `node dist\server\cli.js unlock`） |
| `cards` に `*.invalid-数字` というファイル | 読み込めない名刺ファイルを退避したものです。該当名刺はバックアップから復元してください |
| パスワードを忘れた | サーバーPCで `node dist\server\cli.js user passwd <ID>`（その利用者の全端末のログインが解除されます） |
| サーバーPCが故障 | 別のPCに 1〜7 の手順で導入し、同じ `config.json` を使います。データは共有フォルダにあるため移行不要です |
| 削除した名刺を戻したい | 共有フォルダの `trash` に削除時点のJSONが残っています（画像も保持）。または削除前のバックアップから復元 |

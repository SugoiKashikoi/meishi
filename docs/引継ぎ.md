## 1. 何を作っているか

営業でもらった名刺を、会社名・氏名・「いつ、どこで会い、何を話したか」で検索するための、社内向け Windows デスクトップアプリ（Electron）。

- 各PCのアプリが**社内の共有フォルダのファイルを直接読み書き**する。サーバー・ポート・ログインは無い。
- 複数人で同じ名刺データを共有する。登録者は Windows ユーザーで記録する。
- アプリは外部へ通信しない（CSP と main プロセスでの遮断）。OCR（Tesseract.js）と日本語データは同梱。
- AI での読み取りは、利用者の PC で動く Codex / Claude Code に画像を読ませ、**AI専用フォーム（JSON）＋ `ai-add` コマンド**で登録する。アプリからは AI を呼ばない。

## 2. 利用者について（案内するときの前提）

- 日本語でやり取りする。説明は短く、結論から。専門用語は避けるか一言で補う。
- 費用を抑えたい。無料・追加契約なしの方法を優先する。
- 環境：Windows 11、PowerShell 5.1。Git・Node.js・npm は入っており、PC からインターネットに接続できる。
- リポジトリは `C:\Users\<ユーザー>\Documents\A1projects\meishi` に clone 済み（以前ホーム直下にも clone したが削除を依頼済み）。
- ChatGPT と Claude の両方をサブスク契約している。**AI 登録は ChatGPT（Codex）を使う希望**。
- 参考にしているアプリ：同じ利用者の `SugoiKashikoi/tokuisaki-viewer`（Electron、共有フォルダ上の JSON、ロック＋アトミック書き込み）。画面のイメージは名刺管理サービス「エイト」（名刺画像つき一覧・交換月ごとの表示）。ただし外部サービスの見た目の複製はしない。
- 案内するコマンドは **PowerShell で1行ずつ**、それぞれ別のコードブロックにする。利用者にファイルを手で編集させる手順は避ける。
- 「情シスの目の届かないところで」という発言があったが、本人の意図は「サーバーやポートを使わず、共有フォルダにデータを置くだけの構成にしたい」だった。情シスに隠す運用の手伝いはしない。社内確認が必要な点（署名なし exe の配布、共有フォルダの権限、AI に個人情報を送ること）は、その都度はっきり伝える。

## 3. ここまでの経緯（決定事項）

| 順 | 利用者の判断 | 反映 |
|---|---|---|
| 1 | スマホ・PC から使う名刺管理。データは社内に置き、外部クラウド・生成 AI は使わない | 最初はサーバー版（Node HTTP＋ブラウザ）で実装 |
| 2 | 複数人で共有したい。取り込み用フォルダに各自が画像を入れたい | 利用者ごとのログイン、取り込み用フォルダ（「未整理」画面）を追加 |
| 3 | iPhone「メモ」の書類スキャン（PDF）を使いたい | PDF 内の JPEG を外部ライブラリなしで取り出す機能を追加 |
| 4 | **ポートを使わず、共有フォルダにデータを置くだけにしたい（tokuisaki-viewer のイメージ）。スマホは使えなくてよい** | **Electron デスクトップ版に作り替え**。サーバー版・ログインは削除。複数PCの同時書き込みに対応 |
| 5 | 画面はエイトのイメージ | 一覧を名刺画像つき・交換月ごとに変更 |
| 6 | 登録を AI で楽にしたい。自分の ChatGPT／Claude のサブスクで | まずアプリ内に「ChatGPTで読み取る」（コピー＆ペースト）を作ったが、**利用者の希望で削除** |
| 7 | AI 専用のフォームを作り、アプリを通さずに本体データへ直接登録したい | AI専用フォーム（JSON）＋ `cli.js ai-add`（アプリと同じ保存処理）。AI が `cards/*.json` を直接書くことは禁止 |
| 8 | 写真は名刺部分だけ切り抜いて保存したい | フォームに切り抜き範囲・回転を追加。Electron で切り抜き、`--preview` で AI が確認してから登録 |
| 9 | （Codex 担当分）信頼性向上・Windows ローカル運用セット | `codex/meishi-reliability-local-ai`：ロックの自動奪取をやめる、破損時の保全、AI登録の再実行、同梱 ZIP など |

AI に名刺画像を読ませることは「外部の生成 AI を使わない」という当初の条件の例外。**利用者の判断と社内ルールでの許可が前提**であることを、利用者に伝えてある（ChatGPT の「モデル改善」をオフにすることも案内済み）。

- 利用者は Electron 33 時点で一度ビルドに成功している（`npm ci` で audit の警告が出たが、ビルド用の道具の分が大半と説明済み）。

### B. Windows ローカル運用セット（Codex が追加。`docs/Windowsローカル導入.md`）

- `scripts/package-windows-local.py` で、公式のチェックサムを確認した Node・Electron と OCR データを同梱した ZIP を作る。
- 利用者は ZIP を展開して `Verify.cmd`（配布ファイルの検証）→ `Check.cmd`（接続確認）→ `Start.cmd`（起動）。AI 登録は `AI.cmd dry-run|register <form.json>`（中身は `scripts/production-cli.mjs` → `cli.js`）。
- `meishi-config.json` の `dataDir` と `inboxDir` が必須。
- **B は Windows 実機での確認がまだ。** A と B のどちらを正式な配布方法にするか、利用者とまだ決めていない。

### AI 登録（Codex に頼む文）

```text
docs/AI登録の手順.md を読んで、その手順どおりに名刺を登録して。
保存先は \\fileserver\share\meishi、取り込み用フォルダは \\fileserver\share\meishi-inbox。
```

（B の運用セットでは `AI-REQUEST.txt` の依頼文を使う。）

## 6. 実機テストの手順（利用者に案内する内容）

**必ずテスト用の共有フォルダと架空の名刺で行う。** 本番フォルダ・実在の名刺は使わない。旧版と新版のアプリ・CLI を混在させない（ロックの方式が違う）。

| # | 手順 | 確認すること |
|---|---|---|
| 1 | テスト用の共有フォルダ（例 `\\サーバー\共有\meishi-test`、`meishi-test-inbox`）を用意 | 利用者グループに「変更」権限。他の人は見えない |
| 2 | 1台目でアプリを起動し、保存先にテスト用フォルダを指定 →「フォルダを作成して初期化する」 | 初期化でき、空の一覧が出る |
| 3 | 架空の名刺画像を「＋新規登録」で選択（またはドラッグ＆ドロップ）→「文字を読み取る」→ 反映 → 保存 | 共有フォルダの `cards` に JSON、`images` に JPEG ができる。OCR の候補が出る |
| 4 | 2ページの PDF（表・裏）を選んで登録 | 表裏の画像が入る |
| 5 | 2台目でも同じフォルダを指定 | 1台目の名刺が見える・検索できる。登録者の表示名が出る |
| 6 | 同じ名刺を2台で編集画面に開き、両方で保存 | 後から保存した側に「他の端末でこの名刺が更新されています」。無言で上書きされない |
| 7 | 取り込み用フォルダに JPEG・PDF を置く（複合機のスキャンでも試す）→「未整理」→ 登録 | ページごとに表示され、登録後は元ファイルが取り込み用フォルダから消える（`inbox-done` へ） |
| 8 | 共有フォルダの接続を切る（LAN を抜く等）→ 保存 → 接続を戻す | 保存失敗がはっきり表示され、入力は残る。戻すと30秒以内に再接続。別の場所へ保存されていない |
| 9 | 管理 → 手動バックアップ → 1件追加 →「この時点に復元」 | 追加分が消え、「復元前の退避」ができる。復元中、もう1台の保存は止まる |
| 10 | CSV 出力を Excel で開く | 文字化けなし、電話番号の先頭0が残る |
| 11 | AI 登録：取り込み用フォルダに名刺写真（机の上で撮った架空の名刺）→ Codex に依頼 | `--dry-run --preview` の切り抜き画像を Codex が確認 → 登録。名刺部分だけが保存され、タグ「AI入力」が付き、写真は `inbox-done` へ |
| 12 | 11 の写真の移動を失敗させて再実行（取り込み済みフォルダを一時的に読み取り専用にする等） | 1回目は失敗（終了コード2、名刺は保存済み）。再実行で名刺は増えず、移動だけ行われる |
| 13 | アプリを閉じて再起動、PC 再起動 | 保存済みデータが表示される |
| 14 | 外部通信の確認（任意） | Windows のリソースモニター等で、アプリが社外へ接続していない |

結果は「手順番号・OK/NG・画面の文言かスクショ・時刻」で返してもらうと、原因を追いやすい。

## 7. 未解決の課題（優先順）

1. **古い読み込みロック（`locks/read-*.lock`）が1つ残るだけで復元できない**（中程度）。一覧・詳細・起動のたびに作るロックが、PCの停止・スリープで残ると、`waitForWriters()` が消えるのを待ち続け、35秒で「他のPCの保存処理が終わらない」となる。復元が途中で止まった状態と重なると、起動時の復元再開も失敗し、どのPCも開けない可能性がある（コード上の推定、未再現）。案：読み込みロックをやめる、または読み込みロックだけは更新が止まったものを数えない。少なくとも手順書の残留ロック復旧で `read-*.lock` を消してよいことを明記する。
2. **`maintenance.lock` が残ったときの表示**（軽微）。古いロックでも「他のPCで復元作業中」と出る。「残留ロック。管理者に連絡」と分けたい。
3. **AI 登録が1件ごとに全件を読み直す**（軽微・性能）。`createFromAi()` が毎回 `doRefresh(true)` し、共通ロック `card-ai-import` を持つ。件数が多いと遅い。最初に1回読み込み、以降は差分だけにする。
4. Windows 実機・社内共有フォルダでの確認が全く無い（rename・ロックファイル・時刻のずれ・ウイルス対策ソフト・NAS 機種差）。
5. Electron 45 にしたため、インストーラー（A）を作り直して全PCを一斉に更新する必要がある。
6. 署名なしの exe／ZIP を社内で配ってよいか、情シスへの確認が未了。
7. iPhone「メモ」で作った実際の PDF・複合機のスキャンファイルでの確認が未了。
8. `docs/設計.md` の SQLite 公式資料は、開発環境から sqlite.org に繋がらず原文を未確認。

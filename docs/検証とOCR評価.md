# 信頼性の修正とOCR評価

2026-11-13、Linux / Node 24.22.1で検証。実在の名刺は使用していない。

## 修正

- 復元時の4回のディレクトリrenameの各境界（0〜4回後）で停止しても、起動時に回復する。復元再開時だけmaintenanceロックを取得し、通常起動は読み取りロックで保護して他PCの保存を止めない。起動時に欠落したcards/imagesを作り直さない。
- 期限切れロックを自動で奪わない。スリープ・通信遅延で停止した元所有者が再開しても、別の所有者との二重実行を起こさない。ロックは固有トークンで識別する。全クライアントの一斉更新が必要。残留ロックの手動復旧は導入手順を参照。
- 復元は進行中の読み取り・書き込みの終了を待つ。新しい読み書きは復元中・復元中断時に拒否する。
- 読めない名刺を黙って省いたバックアップを作らない。壊れた名刺・ゴミ箱を原因とする画像の誤削除も停止する。
- 壊れた名刺がある場合も、元バイト列をハッシュ検証済みの保全用tarへ退避してから正常なバックアップへ復元できる。保全失敗時は現在のディレクトリを入れ替えない。
- 自動バックアップの残留ロックを通常の実行中と区別し、ログと状態APIを通じて画面に停止を通知する。
- AI登録の写真移動失敗は終了コード2と保存済みIDで報告する。元写真のハッシュを名刺と一緒に保存し、別プロセス・別名コピーからの再実行や片面だけ移動済みの場合も既存名刺を再利用する。
- JSON解析エラーに含まれる名刺の原文をログに出さず、IDとエラーコードだけを記録する。
- PDF分割名に元PDFのSHA-256を含める。既存結果は内容一致時だけ再利用する。同名で別内容のPDFや無関係の既存JPEGを混同しない。
- 未整理一覧の取得後に元ファイルのサイズ・更新日時が変わった場合、登録・移動を拒否する。複合機には保存済みの名前を上書きせず、一意なファイル名を使う設定を推奨する。
- 電話・携帯・郵便番号・Webを検索対象に追加。電話の区切り文字の違いにも対応。CSV出力前に他PCの変更を取り込む。
- バックアップI/Oの短いread/writeを全バイト完了まで継続し、重複manifestを拒否する。PDFのFlate展開は30MiBで打ち切る。
- OCR候補のカタカナふりがな、同じ行のFAX/TEL分類、独立した郵便番号を修正。表裏のOCR、読み取りの二重起動防止、画像取得エラーの表示を追加。
- Electron 33.4.11 → 45.3.1、electron-builder 25.1.8 → 26.18.0に更新。開発用Nodeの最低要件は22.12に更新。
- 同梱ファイルのコピーではfileURLToPathを使い、空白・日本語を含む開発パスを正しく扱う。

## OCRの比較

`scripts/benchmark-ocr.mjs` で架空人物6名×5条件、合計30枚を生成する。条件は通常配置、左右配置、小さい画像、薄い文字、4度の傾き。同一の新しい候補抽出処理で比較し、文字認識設定による違いを測定した。完全一致はNFKC・小文字化・空白等の除去後に評価する。部署や電話番号を含め、正解を自動で検査する。

| 項目 | 従来の既定設定 | 自動段組み PSM 3 | 採用: 疎な文字 PSM 11 | 大きい4.0.0モデル / PSM 11 |
|---|---:|---:|---:|---:|
| 会社名 | 16/30 | 15/30 | 17/30 | 21/30 |
| 氏名 | 10/30 | 19/30 | 20/30 | 22/30 |
| ふりがな | 24/30 | 26/30 | 25/30 | 25/30 |
| 部署 | 30/30 | 30/30 | 30/30 | 13/30 |
| 役職 | 30/30 | 30/30 | 30/30 | 30/30 |
| 電話 | 30/30 | 30/30 | 30/30 | 30/30 |
| 携帯 | 30/30 | 30/30 | 30/30 | 28/30 |
| メール | 21/30 | 21/30 | 21/30 | 18/30 |
| 郵便番号 | 30/30 | 30/30 | 30/30 | 30/30 |
| 住所 | 24/30 | 20/30 | 24/30 | 0/30 |
| 認識平均時間（初期化除外） | 約351ms | 約365ms | 約356ms | 約488ms |

大きいモデルは同じ固定済みnpm依存に含まれる `4.0.0` の日本語・英語データを比較用に使用したもの。`4.0.0_best_int` と訓練・形式が異なるため、モデル容量一般の優劣を示す比較ではない。住所・部署・メールが悪化したため採用せず、既存の軽量best_intを維持する。PSM 11は氏名が改善したが、ふりがな等で万能ではない。

この評価は架空画像30枚に限られ、実物の名刺での正解率を保証しない。文字の切り出し・会社/氏名の項目分類も誤る。人が確認・修正してから保存する流れは維持した。E2EではOCRボタンを押すだけでなく、架空名刺の電話番号の正解と、裏面英文が読み取れることも確認する。

実行例（Playwrightは開発検証用に別途必要）:

```
npm ci
npm run build
NODE_PATH=/workspace/.setup/node_modules node scripts/benchmark-ocr.mjs /workspace/review/ocr-final
```

Chromiumは既定で `/usr/bin/chromium`。別の実行ファイルは `CHROMIUM_PATH` で指定。`OCR_LANG_PATH` で比較用の言語データフォルダ、`OCR_PSMS=11` 等で測定するモードを指定できる。画像・正解・OCR全文・項目別結果・処理時間を指定フォルダへ保存する。アプリの保存先には書かない。

## 代替エンジン

PaddleOCR / RapidOCRの日本語モデルを比較候補に選定し、隔離したPython環境にRapidOCR 3.4.2とONNX Runtimeを導入した。ただし、公式モデル配布先 `www.modelscope.cn` への接続がクラウドの通信制限で403となり、日本語モデルを取得できていない。日本語以外の同梱モデルで代用して優劣を判断したり、検証していないエンジンへ交換したりはしていない。通信許可の下書きは保存済みで、許可適用後に日本語モデルのSHA-256を公式メタデータと照合して同じ画像で比較する。

- https://github.com/PaddlePaddle/PaddleOCR
- https://github.com/RapidAI/RapidOCR

採用する場合も外部AI・サーバー・ポートは追加せず、モデル・辞書をアプリに同梱してCPUで実行する。Windows配布、CSP、メモリ、モデルライセンスまで検証して決める。

## 検証と残る制限

- 型チェックと回帰テスト40件（失敗0・スキップ0）が成功。表裏OCRを含むデスクトップE2Eも実行。開発版とLinux配布版の両方で、表裏OCR・PDF・2クライアント・競合・取り込み・バックアップ・再起動・外部通信なしのE2Eが成功。
- npm auditは更新前18件（重大1、高13、中4）から更新後6件（重大0、高0、中6）。残る中6件はビルドツールのminimatch由来とその依存関係。最新版electron-builderでも残る。互換性未検証の別メジャーを強制上書きせず、上流修正を追跡する。通常のアプリのOCR・ファイル読み書きではglobパターンをユーザーに評価させない。
- Linuxの配布用ディレクトリ作成と配布バイナリのE2Eが成功。同梱日本語/英語OCRデータを確認し、開発用サーバー・CLIは配布物に含めない。
- Windowsインストーラー、実際のSMB/NAS、スリープや切断・再接続、ウイルス対策との相性はLinuxのローカル試験では保証できない。導入前に実機で試験が必要。
- PDFは汎用レンダラーではなくJPEGストリームの抽出。ページ順とストリーム順が異なるPDF、回転・複数画像の合成、JPEG以外を使うPDFは正しく復元できない場合がある。今回、一般PDF対応までは実装していない。取り込み後の表裏を目視確認し、複合機の実際の出力形式を事前検証する。任意PDFへの完全対応が必要ならローカルPDFレンダラーへ置換する。
- ロックは共有フォルダの排他作成・renameの正常動作を前提とする。自動奪取をやめても、NAS自体が排他を保証しない場合や管理者が稼働中のロックを消す場合まで保証できない。
